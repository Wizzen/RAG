# 对象、属性与分层取值：知识图谱 V2

状态：已实现。迁移 `0034_hierarchical_knowledge` 新增模型，页面及命令默认输出 V2；原有关系和任务历史继续保留。

表格增强已接入正式 V2 流程：AI 选择已读表格和主体/分类方向，程序按原始行列构建候选，正文说明与复杂条件继续使用证据抽取。
表格相关条款随每条候选保存，避免仅取数值丢失适用范围；矩形 Markdown 表、两种分类方向和无歧义相邻续行已覆盖。
HTML 合并单元格可从原始正文恢复，并与已读索引逐行核对；多因素矩阵支持按结果等级组织 OR 条件组和组内 AND 条件，
关联表格或正文中的阈值和适用说明。规则使用 `value.type=rule`，沿用现有 JSON 字段、来源版本与逐条审核，不需新增迁移。
表头不明、原文与索引不一致、图片单元格或归属冲突仍提示复核；当前没有把所有条款逻辑推断自动化。

默认界面按“对象 → 属性 → 分类项 → 子属性”展开，点击内容查看取值、条件、原文与圈注，并逐条确认。
新提示默认向同一资料集合中的同名同类型对象追加分支；跨集合追加需要在可选的“跨资料追加到已有对象”中明确选择目标。
不同标准、版本、方法分别保存分支；没有标准标识时按源文档隔离。列表、范围和结构化字段可在详情中展开。

旧关系转换使用 `python manage.py graph_upgrade --kb SLUG --run ID` 预览，添加 `--apply` 执行；不调用模型。
转换只接受仍能在当前原文中校验的已支持关系，生成新的待确认内容，不继承旧审核状态；重复执行不会重复创建。
不支持或依据不足的旧关系仍保留在“旧版关系图与历史记录”。新一轮抽取会直接使用分层契约。

## 目标

围绕一个可持续扩充的对象组织知识：对象 → 属性 → 分类项/取值 → 子属性 → 更细的取值或内容。
对象的属性不预先固定。新文档、新知识库或新的关注提示可以提出已有对象下的新分支。
每一层均允许多个子项；节点可以同时具有说明内容、多个取值和更细的子属性。

例如下面仅表达结构，不代表原文已经支持或审核通过所有条目：

```text
锻件
├─ 质量分级〔检测方法：UT；适用标准/版本：来源限定〕
│  ├─ I 级
│  │  ├─ 等级定义 → 原文支持的说明
│  │  └─ 判定条件
│  │     ├─ 单个缺陷当量平底孔直径 → 阈值、比较符、单位
│  │     └─ 底波降低量
│  │        ├─ 允许值 → 阈值、比较符、单位
│  │        └─ 适用条件 → 原文支持的条件
│  ├─ II 级 → 定义、判定条件、例外条件……
│  ├─ III 级 → 定义、判定条件、例外条件……
│  ├─ IV 级 → 定义、判定条件、例外条件……
│  └─ V 级 → 定义、判定条件、例外条件……
└─ 后续主题提出的新属性
   └─ 内容、取值列表或更细的子属性……
```

I～V 是质量分级属性下的分类项；不能把所有对象的“I 级”合并成一个节点。
没有读取到或没有证据支持的等级、定义和条件保留为缺失，不按示例补齐。

## 当前结果为什么难用

本地第 28 次抽取已完成，生成 20 条候选。当前表示把“锻件 → 单个缺陷当量平底孔直径”保存成关系，
把质量等级塞在 `qualifiers.quality_grade` 或 `qualifiers.质量等级` 中。
这使“质量分级 → I～V 级 → 各级条件”的组织方式没有进入图谱。
`V`、`V级`、`V 级` 也缺少所属属性和上下文的统一身份。

抽取定位、原文内容和圈注可以继续使用；需要调整的是抽取契约、知识存储、增量归并、检索和默认展示。
只修改连线布局不能补回这些结构。

## 核心模型

### KnowledgeObject：知识对象

保存对象身份、名称、类型与资料集合作用域；断言另存原文对象名称。对象可以是材料、设备、产品、业务概念等。
“锻件”与“锻钢件”是否同一对象需要依据和确认，不能靠名称相似直接合并。

### KnowledgeNode：递归知识节点

关联所属对象和父节点，具有稳定路径与语义角色：属性、分类/列表项、子属性或分组。
节点名称保持业务原词，如“质量分级”“I 级”“底波降低量”；节点不要求具有数值。
同一节点可以有多个子节点，也可以同时承载取值/说明断言。
引用内容可使用 reference 类型保存；自动解析跨对象跳转和别名归并尚未实现。

### KnowledgeAssertion：带来源的取值或内容断言

挂在明确的对象及节点路径上，支持文本、数值、范围、多个值、对象引用与结构化内容。
数值保留比较符、单位和原始表示；多个取值分别携带其条件与来源。
判定规则保留 AND、OR、例外与否定，不能把“同时满足”和“满足任一项”画成相同的列表。

断言具有独立的候选/已确认/拒绝状态；确认一个分组不会自动确认所有后代内容。
审核时显示完整路径、适用条件以及与聊天页相同的原文页码和圈注。

### KnowledgeEvidence：断言证据

复用现有逐字引文、补充表头引文、文档版本摘要和 chunk/页码/圈注定位。
布局路径可以帮助组织和浏览知识，断言进入问答仍须通过原文校验和人工确认。

## 增量与多来源

- 在同一授权作用域内，通过对象身份、父路径和上下文定位已有节点；新的主题增加分支，不重建或覆盖整棵树。
- 属性定义可复用；属性的具体取值和条件属于来源断言。不同标准或版本的冲突值并列保留，不能后写覆盖。
- 检测方法、对象范围、标准版本等上下文参与分支识别。不同检测方法的同名“质量分级”不能混在一起。
- 跨知识库扩充依赖明确的对象绑定/归并关系，并逐条保留来源知识库权限；不得因同名而全局自动合并。
- 同一事实的多份证据可以汇集；新来源、新路径或新解释产生的候选不能继承旧审核结论。
- 来源修改或退休后，仅撤销依赖它的断言资格；其他仍有效的来源可以继续支持相应知识。

## 新抽取契约

模型输出对象引用、结构路径和具有证据的叶部断言；路径支持分类项与子属性的交替嵌套。
例如 `锻件 / 质量分级〔UT〕 / I级 / 判定条件 / 底波降低量`。
每条断言必须提供自己的逐字证据，并为跨片段的对象名、等级和表头提供支持引文。
结构标签也不能扩展原文含义；组织分组与原文事实需在接口中明确区分。

召回仍采用当前向量与关键词混合搜索，保留模型按需补读邻文、32k 单轮输出、有限调用预算及截断保护。
保存前验证路径归属、来源条件、值类型和证据，而不是把所有参数都强制成一个数值比较关系。

## 展示与问答

默认展示可展开的对象层级：先选对象，再看属性和子属性。展开质量分级才看到各等级，点击某一级查看定义与细则。
长内容、数值集合和表格在详情区完整展示，不把它们挤成长节点标签。
旧版实体关系仍可在折叠区域沿连线浏览；V2 的层级树是主要浏览方式。

问答按“对象 → 属性路径 → 适用上下文”定位已确认且来源有效的断言，返回完整条件和证据。
存在多个标准、版本或方法时保留区分；条件不足以选出唯一答案时不擅自选一个。

## 验收与后续

已接入 V2 存储、抽取、浏览、逐条审核和已确认内容的问答检索；引用快照会随来源变更、权限撤回或审核撤回而失效。
测试使用模拟的 I～V 级及多值、子属性、增量追加、标准隔离和来源权限数据，不把模拟等级作为真实标准要求。
实际检索质量仍需通过用户文档和标注问题检验；模型定位正确不等于每条层级解释已获确认。

验收至少覆盖：同一对象追加新属性、属性下多等级与多条件、子属性继续细分、同名等级不串对象、
不同标准不相互覆盖、候选不参与问答、权限撤回后无法通过共享对象读取隐藏来源。
旧三元组转换只产生 V2 候选；不得删除旧数据或自动批准新的层级解释。
