# 远程回答 API

在「设置 → 回答模型 → 编辑」勾选「允许远程回答 API」，填写服务的 HTTP 或 HTTPS Base URL、API Key 和模型 ID，保存配置后点击回答模型测试，或一键全部测试。例如 Base URL 为 `https://api.example.com/v1`，系统追加 `/chat/completions`，不要填写完整的聊天端点。局域网示例为 `http://192.168.1.100:1234/v1`；不强制选择 HTTP 或 HTTPS，但非本机地址仍须开启远程开关。

仅支持 OpenAI 兼容 Chat Completions API；供应商还需支持工具调用和流式响应才能完成现有检索问答。连接测试只验证最小非流式回答，不代表工具调用与完整问答已验收。不直接支持原生 Anthropic / Gemini 协议。

开关默认关闭，已有配置、旧预设不会自动启用外发。启用后，回答、问题规划和核对将向该服务发送问题、历史对话和检索资料；开启视觉后也可能发送图片。向量、OCR、重排仍使用各自配置。当前配置改变在下一次请求生效；请等正在生成的回答完成后再切换。

`FOS_LOCAL_ONLY=1` 时，网络边界只例外放行所配置回答端点的主机和端口，以及其 DNS 解析得到的地址。这是进程级地址放行，不是按 HTTP 路径隔离。浏览器外部资源仍受原有 CSP 限制，模型下载离线标记保持开启。不使用系统代理，不跟随重定向。关闭开关后新连接不再放行，已经建立的请求不会被强制中断。`FOS_LOCAL_ONLY=0` 本身不提供全进程出站限制。

远程模式不发送 `LLM_EXTRA_BODY` 中的本地引擎参数，也不请求可选的流式 usage。远程 API 不兼容工具调用、达到配额、超时等情况仍会报错，不自动回退云服务或换模型。密钥仅填写于管理员设置，不写入仓库。

部署需先执行 `python manage.py migrate`（新增 0027），再重启 Web。回退时关闭开关、加载本地回答预设；恢复旧代码可保留新增数据库列，无需删除业务数据。

本次验证：170 项 Django 全量测试通过（包含 HTTP/HTTPS、局域网端口隔离、DNS 放行与撤销）；23 项 Node 测试通过；迁移一致性检查通过。远程协议请求由 mock 验证，未获得用户的真实供应商配置，未进行真实远程问答验收。
