# 知识图谱辅助检索

## 对象属性树与逐条审核

文档主题抽取默认使用 V2：`对象 → 属性 → 分类项/列表项 → 子属性 → 取值或内容`。属性名和深度按原文组织，不要求预定义全部参数。
默认“对象知识”界面按资料集合累计显示多个提示生成的属性；点击叶部内容查看完整值、适用条件、逐字原文及 PDF 圈注。每条内容均需单独确认后才参与问答。
不同标准、版本和检测方法的同名属性分开保存，冲突内容并列保留。跨资料集合扩充需显式选择可见的已有对象，内容始终按各自来源库校验权限。
“只看本次抽取”可切回单个批次；旧图形与关系列表保留在折叠的“旧版关系图与历史记录”。详细模型和转换说明见 [知识图谱 V2](knowledge-graph-hierarchy.md)。

## 旧版 G6 交互探索

主页面只选择一次资料，按知识库分组展示所有可见且已解析正文的文档；该选择同时决定抽取目标、图谱和历史任务范围。填写关注主题后点击「开始构建」。生成进度保持简短，原始输出、工具活动、筛选历史和高级工具默认折叠；切换资料通过 AJAX 更新，并保留已填写的关注主题。资料页带已有文档知识库参数时自动选中该文档。

当前集成 AntV G6 5.1.1，图形与文字列表使用同一套 Django 图谱和权限。文档到候选图谱、来源检查的交互参考 [Neo4j LLM Graph Builder](https://github.com/neo4j-labs/llm-graph-builder)，受控实体和关系词表参考 schema 引导的思路；本版没有部署 Neo4j，也没有引入其 Graph Builder 后端或 KAG 引擎。

- 选择资料后，「筛选与历史」可按任务、状态和实体名称查看。拖动画布、滚轮缩放；点击实体展开关联。不同条件的关系分别绘制，主流程无需再次选择知识库或文档。
- 点击连线，在侧栏核对关系、适用条件、原文、页码和 PDF 红框。每条关系单独确认、拒绝或退回待核对；只有已确认且来源仍有效的关系参与问答。
- 橙色虚线为候选、绿色实线为已确认、红线为拒绝、灰线为来源失效。普通用户只收到已确认且有效的数据。图谱数据和单条详情接口均在服务器重新校验知识库范围、来源状态和权限。
- 每页最多100条关系，使用「上一页关系／下一页关系」遍历当前筛选全部结果；管理者可看到当前筛选的总条数，分页不限制生成总量。每次邻接展开最多100条，单个展开视图最多300条。批次、状态和权限继续约束展开。下方「文字列表与任务进度」同步当前页，提供文字访问方式及图形加载失败时的入口。

G6 浏览器包、MIT 许可证及来源信息保存在 `static/js/vendor/`，从本地静态路径提供；用户浏览图谱不需要访问第三方 CDN。升级时审查并更新 `scripts/vendor_g6.py` 的版本与 SHA-512 完整性值，再执行该脚本。来源：[G6](https://github.com/antvis/G6)、[平行边配置](https://g6.antv.antgroup.com/manual/transform/process-parallel-edges)。

聚焦抽取使用 `kb/graph_schema.py` 的受控词表；同义的 failure/fault/defect_type 统一为 defect。分类和组成关系分开，拒绝表格序号、无指向主体、缺少参数/比较符/数值/单位的参数断言，以及部分明显的否定方向错误。实体类型保持封闭词表；谓词优先复用现有清单（prompt 附中英对照），不贴切时允许模型自创小写英文 snake_case 谓词，展示侧未知谓词按英文原样显示。这些检查只排除已知错误，不证明模型断言正确，也不替代人工确认；旧结果不会被自动改写或重新批准。

## 自动从现有文档构建

### 按原表行列生成知识

V2 默认在已读片段中建立 `table_catalog`。模型选择表格、原文主体、属性和分类方向，调用
`build_table_knowledge`，或在最终 JSON 的 `table_requests` 中给出相同选择；无需重复输出单元格数值或拼接表格引文。
程序直接从原始表头、行列对应关系生成“对象 → 属性 → 分类项 → 子参数 → 取值”，保留公式和不等号原文。
首行分类与首列分类均可处理；`parameter_names` 可限制本次方面涉及的参数，不因为表格被召回就展开无关内容。

表格到了片段边界时，模型须先补读相邻正文以确认是否有续表。只合并已读且相邻、列数一致且无歧义的连续数据行；
Markdown 重复表头或行列不齐会明确提示，不猜测缺失内容。HTML 表格从保存的原文恢复 rowspan/colspan，
逐行核对已经读取的索引内容，无需重新 OCR 或嵌入；表题后的单位说明和表下注释一并保留。主体必须得到表格标题或所属章节支持，
不能把其它材料章节的标题借来给当前表格改名。表头和每行都有各自的实际 chunk 及逐字引用，继续使用原文页码/圈注。
重复表头的页码按保存的原文片段解析，避免同样文字出现在其它表格时误跳；旧证据没有唯一定位时只显示引文。

同节相关条款及明确的表后注释随每条候选保存在 `conditions.source_notes`，同时保留原文证据。
它们是带原有作用范围的来源说明，不自动改写成同时满足、任一满足或通用于所有缺陷的条件。
用户确认一条取值时能一并核对这些说明；问答事实快照也保留它们，避免只引用阈值而丢掉近场条件或独立分级要求。

表格构建与搜索/邻文工具共用8次工具请求预算，不另起无上限扫描或模型查漏。
每次最多生成160项，超出需明确缩小参数范围；只保存候选，仍须逐条人工确认。
`coverage.tables_built`、`table_candidates` 记录程序构建情况，与模型 JSON 输出页数分开计算。
界面将常见 LaTeX 比较符、φ 和单位标记转成易读文字；数据库原值、事实版本和原文引用保持逐字表示。

### 综合等级与多因素判定

行条件与列条件共同决定结果的矩阵使用 `build_table_knowledge(layout="decision_matrix")`，
显式指定 `header_rows`、`row_parameter`、`column_parameter`。同一结果对应的多个格子构成 OR，
每格的行列条件构成 AND，保存为 `对象 → 属性 → 结果等级 → 判定条件` 下的一条 `value.type=rule` 候选。
`content.any_of[].all_of[]` 保留每个条件的原文参数名和分类要求；不把单个局部阈值直接当作综合等级。
界面按条件组展开，原文说明默认折叠；左侧树只显示组合数量，完整条件仍保留在详情与问答快照中。

`bindings` 可按分类名称精确关联其它已读定义表：`parameter` 指本矩阵的条件名，`table_id`、
`match_column`、`value_columns` 指来源表及从0开始的分类/取值列。正文定义使用 `entry`、
`source_chunk_id`、`quote`，`context_quotes` 保留适用工况。定义中的数值、公式、材料列名及说明按原文复制。
分类没有对应定义时明确报缺失，不借用其它分类或材料的阈值；关联说明不自动改写为额外的全局 AND。
规则当前用于浏览、审核和有来源的问答，不作为自动验收或规则求值引擎。

候选校验失败会显示具体原因，最多在原有模型、续页及耗时预算内修正一次，不重新检索。
逐字引文校验不放宽，`saved_relations/saved_assertions` 摘要不能冒充新断言；修正后仍未通过则保留已有候选并标明未完成。
MinerU 将表格正文放在字符串 `text` 中时也能解析表格版面圈注；原有溯源须刷新映射后使用新框，不需要重跑 OCR。

### 按主题召回，再按需补读

页面及 graph_extract 命令默认使用 `kb/graph_focus.py`：先按用户关注主题召回最多6段正文，然后由模型决定是否调用工具补读相邻片段、引用表格或相关章节。已读原文足够即可直接输出；没有相关事实可返回空列表，不强制补查。默认不扫描全篇、不另做查漏、不递归拆分重做。旧系统扫描代码仅供历史兼容，不是页面或命令的默认入口。

首次召回和补充搜索均采用 `kb/graph_retrieval.py` 的语义向量与关键词双路召回，RRF 融合。查询在 Chroma 中按当前文档 source 和当前正文 ids 前置过滤，再限制 top-k，最终结果映射回当前正文。使用站点已配置的嵌入模型和现有索引，不重新嵌入文档。向量服务不可用时明确提示回退关键词；零命中时可参考目录定位，不能据此断言资料没有相关内容。

整个任务共用最多8轮模型调用、8次工具请求、4页输出、24个已读片段及24000原文字符；累计输入160000字符、累计公开输出131072字符、600秒后停止后续生成。流式接收中也检查时间和输出预算；模型连接另有网络读取超时。每轮最多32768 tokens（32k），提示每页最多12条、使用精简逐字引文；`has_more` 用于有限续页。截断时仅从 JSON 数组中取出完整元素，仍经过相同的原文、片段及领域校验后保存为候选，半条关系丢弃；随后缩小单页输出条数，在原预算内续写。没有新增有效事实的截断最多额外尝试一次，不重新检索或扫描原文。续页仅带回已保存事实的短摘要，不重复发送长引文或损坏尾部；截断不能标记为全部完成，达到预算时保留已有候选并明确标记未完成。

候选逐页保存；同一运行中相同主体、关系、客体与条件合并，保留不同原文证据，不同条件分别保存。表头与数据行分离时，`supporting_quotes` 保存额外的逐字表头引文，每段均核对实际已读正文及片段身份。原文版本变化会停止后续调用与保存。

`GraphExtraction.coverage.mode=focused` 记录实际读取的片段、模型和工具次数、累计输入/输出字符，以及服务端回报的 token 用量；未回报时明确显示用量未知。页面显示“已读取 / 模型调用 / 补查”，不将召回范围冒充全文覆盖率。“主题抽取已结束”只表示本次有限任务结束，不证明全书事实穷尽。旧任务的系统扫描记录继续按原方式展示。

### 实时生成过程

管理员点击「开始构建」后，页面自动选择本次任务。默认只显示简短进度；展开「查看生成过程和原始输出」可查看实际模型文本增量、正文补查、邻文工具调用、结构与逐字引文校验数量、候选预览和失败信息。片段旁可打开与聊天页相同的原文圈注。结构与引文检查通过不代表语义已获人工确认；候选仍不能用于检索，直到逐条审核通过。

后台使用模型原生 `stream()`，短文本增量合并后写入 `GraphExtractionEvent`；前端通过带游标的只读 SSE 接收。刷新页面或重连会重放已有活动并接着读取，不会重启模型调用；切换知识库关闭原订阅。可选择旧任务查看记录，并关闭「跟随最新输出」以停留阅读。只有相应文档库的管理者可访问原始流和候选预览，流连接每批重新检查权限。日志随任务或源文档删除而级联删除。

模型文本最多保留 24 万字符，达到时明确提示但继续完成抽取；只展示公开文本，不读取内部 reasoning 元数据。若模型端自身缓冲输出，界面只能在该端返回数据时更新。升级前运行的任务没有流记录，不能重建当时的逐字输出；旧任务结果仍可审核。当前后台任务仍依赖应用进程持续运行，SSE 重连不恢复被应用重启中断的任务。

图谱页选择已完成索引的资料，填写本次关注主题，点击「开始构建」。上传不会触发无方向的全书抽取。先提供召回的相关正文，模型可调用 search_document_chunks 做混合检索、get_document_chunks 按目录跳转、get_neighbor_chunks 补齐相邻正文。每次保留独立的关注提示、读取范围和运行记录。

候选包含实体、明确关系、适用条件和逐字正文证据。引文必须连续存在于实际读取的一个片段中。每次运行生成独立待确认结果，即使先前运行的同一结论曾获批准，也不会继承批准。每条明确点击确认前不能进入图谱召回或问答。条件和否定信息直接显示。

结果旁显示原文，并复用聊天页的 evidence_panel.js。存在 ChunkProvenance 时显示页码并打开原 PDF 页的红框圈注；旧文档没有版面映射时明确显示无页码定位，不伪造圈注。重建索引后按引文重新解析当前块 ID。

搜索、目录跳转和邻文读取共用整个任务的8次工具请求及8次模型调用；重复或无效请求也计入预算，相同查询缓存，工具只返回尚未提供的正文。每次搜索最多4段、目录跳转最多3段、邻文读取最多2段，均限当前资料。目录最多显示32个章节片段，超出时采样并标记不完整；目录不能作为引用。相邻读取须以实际已读片段为起点，最终引文必须来自实际读取正文。

V2 对象在资料集合内按类型和名称复用，分支仍带各自标准、方法和来源上下文。旧版实体按文档作用域保存；高级的手动补充关系引用仅作为旧版修正入口。

```console
python manage.py graph_extract --kb YOUR_KB_SLUG --focus "检测人员的视力要求"
```

任务状态持久化，执行由单工作线程串行处理。同一文档有运行中任务时不重复调度。当前调度依赖应用进程持续运行，尚非独立任务服务；进程中断留下的运行状态需要运维核对后恢复。

提供设备 → 部件 → 图纸关系，以及人工关联的手册原文。结构化字段先生成候选，管理员核对后才参与两跳检索。问答可直接引用已核对的关系及原始行，也可通过关系召回手册片段。人工核对范围限于关系及适用条件，不代表原始行所有字段或模型延伸解释均已确认。

## 使用

1. 执行 `python manage.py migrate`，打开 `/kb/graph/`（导航「知识图谱」）。
2. 选择一次资料，填写关注主题后点击「开始构建」。CSV/XLSX 的显式业务字段构建入口保留在「高级工具」。
3. 在“对象知识”展开属性、分类项和子参数，点击具体内容核对取值、条件和原文，再点击「确认此条内容」。普通用户只能查看已确认且来源有效的内容。
4. 文档自动抽取已附原文证据，可直接查看。仅需人工修正或补充时，展开高级选项关联其它原文；没有匹配到当前关键词索引块时不会生成伪引用。
5. 在该知识库的问答中指定对象及属性，或使用完整设备/部件/图纸编号。`kb_graph_search` 直接返回已确认内容与来源，无需重新 embedding。需要进一步解释、检修步骤时继续检索手册；图谱召回原文与向量、关键词候选通过 RRF 融合并统一精排。

## 直接事实问答与引用

图谱工具返回独立的 `kind=graph` 证据快照，包含关系、实体身份、适用条件、审核信息和来源版本。回答模型组织表达；调用图谱后，回答必须通过语义核验及来源检查才发布，即使站点关闭普通问答增强。来源失效、权限改变、审核撤回或核验不可用时不发布草稿。

引用芯片使用来源文件名、工作表和行号。点击打开 `/kb/graph/fact/<关系ID>/?v=<版本>`，重新检查权限和来源；版本改变返回 410。历史消息重新载入也核对快照。图谱和文档引用分别去重。

单次最多返回 12 条事实、16000 字证据；不截断单条的适用条件，超过总预算时返回范围不足提示。旧版关系另有单条6000字保护。缺失不是否定证明，两跳路径不能自动推导因果。图谱问答导出使用核验后的固定 CSV 写入器。

已有业务表没有知识库归属，迁移不会猜测。全局管理员可在图谱页把未归属数据集明确归入目标库；部门管理员不能领取旧的无归属数据集。批量补建已归属数据：

```console
python manage.py graph_backfill --kb YOUR_KB_SLUG
```

命令及页面补建均幂等，不覆盖审核结论。它们只创建候选，不自动批准事实。新版本文件重新生成候选，需要重新核对。

## 身份与证据

- `GraphEntity`：知识库 + 类型 + 业务命名空间 + 规范编号共同确定身份；类型和别名字段可扩展。
- `GraphRelation`：有向主语/谓语/宾语、适用条件、来源身份、审核人及时间。每份原始行的断言独立保留，不把来源重复计数当作真值证明。
- `GraphEvidence`：结构化原始行或文档原文（严格二选一），保存来源摘要。图谱实体和关系不依赖 embedding 或 chunk ID。
- `StructuredDataset.kb`：结构化数据的知识库边界。旧无归属表保留原有搜索可见性，但不参与图谱。

编号只规范 Unicode、大小写和空白；保留 `-` 等符号，`P-1` 不会与 `P1` 合并。设备上下文不同的同号部件分开保存；缺设备编号时使用数据集独立命名空间，不自动跨表连线。明确同一设备的多份表可以通过相同设备/部件编号连接。

数据集退休、原始行修改或删除后，其关系立即失去检索资格。手册内容修改、删除、状态变化后，对应文档证据失效。补充手册证据不能使退休的业务行重新生效。单纯重新 embedding 时从当前关键词索引解析新的 chunk ID，不需要重审未变化的原文。

## 检索边界

图谱检索只使用调用方允许的知识库。问答选中文件夹时显式允许文件夹关系及可见子库原文；选择单文档库时不自动扩大到父库。原文证据还必须落在允许的文档库范围内。关系路径用于定位证据，不额外插入未经过原文核验的图谱断言到模型上下文。

两跳遍历允许正向和逆向寻找相关资料，显示时保留事实的实际方向。从部件逆向到设备后不会再扩散到该设备所有兄弟部件。多个同号/同别名实体无法消歧时不自动选一个；可同时指定设备编号。图谱缺失、故障或没有匹配时保持常规检索。

本版限制：每次实体候选检查最多 2000 个、种子最多 12 个、每轮边最多 300 条，界面最多 100 条关系；达到上限会提示缩小范围。检索结果不是穷尽证明，没有找到也不代表关系不存在。数据量扩大前应改为索引化实体解析，并用评估数据调整预算。

## 后续扩展

核心模型不限定设备领域。新增业务领域可增加受控的 `kind` / `predicate` 适配器，复用候选审核、来源摘要和检索逻辑。后续可增加实体别名/合并审核、手册关系抽取，以及真实问题集上的对照评估。结构化事实使用独立证据类型，不冒充手册 chunk。

## 验证

图谱实时面板区分「重新连接日志」与「重试抽取」：前者仅重放同一任务的日志，后者仅对失败任务新建一次抽取，保留原有候选。重试重新校验管理权限、文档归属及原文版本。

模型传输中断时，整个主题任务最多自动重试一次当前请求，不重做已保存的页，不重新检索；重试仍消耗原有 8 次调用、累计输入和 600 秒总预算。每次模型请求连接超时 10 秒、无数据读取超时 90 秒，并用可取消的异步流限制单次总耗时 180 秒（包括没有公开输出的等待）。JSON、引文、权限等校验失败不自动重试。

多轮补读始终保留工具定义，不在固定轮数后切回普通模型。工具额度用尽或只剩最后一次模型调用时，保留相同工具定义并设置 `tool_choice=none`，要求仅根据已读正文输出最终 JSON。原始 `<tool_call>` 标签、空响应和非 JSON 内容会报告明确的格式或协议错误，不作为图谱结果接纳。

面板显示每轮请求的等待和完成耗时；失败原因和重试按钮位于日志折叠区外。进度读取失败或超时后继续轮询，终态历史重连不会反复触发完成刷新。模型输入只包含正文、表头和来源标识，圈注坐标等仅用于界面；导航目录最多 32 项，未显示的正文仍可通过文档内搜索工具定位。
